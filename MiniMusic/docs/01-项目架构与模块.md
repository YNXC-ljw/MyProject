# 架构与模块

## 一、整体分层

项目按四层组织,核心原则是:**界面层不直接操作播放器和数据,而是发出信号,由业务层统一调度。**

| 层 | 包含的类 / 文件 | 职责 |
| --- | --- | --- |
| UI 层 | `qqmusic.ui`、`BtForm`、`RecBox`、`RecBoxItem`、`ListItemBox`、`MusicSlider`、`VolumeTool`、`LrcPage`、`CommonPage` 的显示部分 | 只负责显示,把用户操作转成信号 |
| 业务层 | `QQMusic` 的槽函数(`onXxx`)、`CommonPage` 的筛选逻辑、`LrcPage` 的解析与查找 | 接收信号,协调数据层与播放核心层 |
| 数据层 | `Music`(单曲数据)、`MusicList`(歌曲集合)、SQLite 的 `musicInfo` 表 | 保存与提供歌曲数据、收藏与历史状态 |
| 播放核心层 | `QMediaPlayer`、`QMediaPlaylist`(底层由 Qt Multimedia 的平台后端解码) | 解码播放、播放队列、进度 / 音量 / 元数据 |

## 二、模块职责

| 模块 | 一句话职责 | 对外提供 |
| --- | --- | --- |
| 主窗口 `QQMusic` | 程序调度中心:初始化界面、播放器、数据库,连接所有信号槽 | 各类槽函数、`musicList`、`player`、`playList` |
| 歌曲模型 `Music` | 描述一首歌,负责解析元数据与写库 | 歌名、歌手、专辑、时长、路径、`isLike`、`isHistory`、`musicId` |
| 歌曲集合 `MusicList` | 管理全部歌曲 | 加载过滤、路径去重、按 ID 查找、读写数据库、支持范围 for |
| 列表页 `CommonPage` | 三个列表页的共用实现 | `setCommonPageUI`、`reFresh`、`addMusicToPlayList`、若干信号 |
| 自定义控件 | 提供统一的界面组件 | 各自的 `setXxx` 接口 + 信号 |
| 歌词窗 `LrcPage` | 解析并显示 LRC 歌词 | `parseLrc`、`showLrcWord`、`getLineLrcWord` |

## 三、模块之间的关系(谁调用谁)

调用方向只有两条,记住这两条就不会乱:

1. **UI 层 → 业务层(向上发信号)**
   控件不认识数据库和播放器,只发信号,例如:`BtForm::click`、`CommonPage::playAll`、`ListItemBox::setIsLike`、`VolumeTool::setMusicVolume`。

2. **业务层 → 数据层 / 播放核心层 → 再刷回 UI 层**
   主窗口收到信号后:调 `MusicList` 取数据、调 `player/playList` 控制播放,最后调用界面的刷新函数(如 `reFresh()`)。

```text
            信号
控件 ─────────────────→ 主窗口 QQMusic
(UI 层)                      │      │
                            │      │
                 调用数据    │      │   调用播放器
                            ↓      ↓
                        MusicList   QMediaPlayer / QMediaPlaylist
                        (数据层)     (播放核心层)
                            │
                            ↓
                      SQLite(持久化)

            刷新
主窗口 ─────────────────→ 各页面 / 控件
```

## 四、界面是怎么调用播放器功能的?

**答案:界面不直接调用播放器,而是通过信号槽交给主窗口。**

以"点击播放/暂停按钮"为例:

```text
用户点击播放按钮
   ↓  Qt 自动连接:clicked() 信号
主窗口槽函数 onPlayClicked()
   ↓  读取播放器状态 player->state()
   ├─ Playing → player->pause()
   ├─ Paused  → player->play()
   └─ Stopped → player->play()
   ↓  播放器状态变化,发出 stateChanged 信号
主窗口 onPlayStateChanged() → 更新按钮图标
```

其他功能同理:

| 界面动作 | 发出信号 | 主窗口怎么调播放器 |
| --- | --- | --- |
| 点上一曲 / 下一曲 | `clicked()` | `playList->previous()` / `next()` |
| 点播放模式 | `clicked()` | `playList->setPlaybackMode(...)` |
| 拖动进度条 | `setMusicSliderPosition(比例)` | `player->setPosition(比例 × 总时长)` |
| 调音量 | `setMusicVolume(int)` | `player->setVolume(...)` |
| 静音开关 | `setSilence(bool)` | `player->setMuted(...)` |
| 双击列表某首 | `playMusicByIndex(页面, 行号)` | 清空队列 → 装歌 → `setCurrentIndex(行号)` → `play()` |

## 五、把一件事从头串一遍(建立整体感)

以"把一首歌从磁盘加载到播放"为例,你会用到全部四层:

```text
1. UI 层:用户点"添加本地音乐" → 主窗口 on_addLocal_clicked()
2. UI 层:弹出 QFileDialog,选中若干文件
3. 业务层:调用 musicList.addMusicByUrl(...)
4. 数据层:用 QMimeDatabase 过滤音频格式;用 QSet 判断是否已加载(去重)
5. 数据层:构造 Music 对象,解析元数据(歌名 / 歌手 / 专辑 / 时长)
6. UI 层:调用 localPage->reFresh() 把歌曲显示到列表
7. 业务层:用户双击某一行 → 清空 playList → 按页面类型重新装歌
8. 播放核心层:player->play(),并通过 positionChanged 等信号回传状态
9. UI 层:根据回传信号更新进度条、时间、封面和歌词
```
