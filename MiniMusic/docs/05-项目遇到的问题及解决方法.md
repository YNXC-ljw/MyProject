# 项目遇到的问题与解决

> 用途:面试问"你在做这个项目的时候遇到过哪些问题?怎么解决的?"时用。
> 每一条都按 **现象 → 原因 → 解决 → 一句话话术** 组织。面试官想听的不是"我遇到了 bug",而是"我怎么定位、怎么判断、改完为什么就好了"。

## 一、界面开发阶段

### 1. 无边框窗口关不掉、也拖不动

- **现象**:设置 `Qt::FramelessWindowHint` 之后,窗口没有标题栏,既找不到关闭按钮,也没法用拖动标题栏的方式移动窗口。
- **原因**:无边框把系统标题栏整个去掉了,而关闭、拖动这些能力本来就是标题栏提供的,得自己补回来。
- **解决**:关闭先临时用任务栏右键关;拖动则重写鼠标事件——按下时记录光标相对窗口左上角的偏移 `dragPosition`,移动时用 `move(event->globalPos() - dragPosition)` 让这个偏移保持不变。
- **话术**:"无边框等于把系统本来帮我做的事都收回来自己做。"

### 2. 阴影半径设大了,窗口显示不全、刷新异常

- **现象**:给窗口加 `QGraphicsDropShadowEffect` 之后,窗口边缘显示不全,歌词窗口的动画也不正常。
- **原因**:阴影的模糊半径(blurRadius)设得太大,和窗口的 geometry 动画互相干扰。
- **解决**:把模糊半径控制在小值(10 左右),不要贪大。
- **话术**:"效果参数不是越大越好,它和动画、重绘是互相影响的。"

## 二、列表刷新阶段

### 3. 歌曲刷新到界面后不立刻显示

- **现象**:`reFresh()` 里把 `ListItem` 都设置好并加进 `QListWidget` 了,但界面上有时候看不到,得把鼠标移到列表上或者触发一次界面刷新才显示出来。
- **原因**:往界面里加元素这个操作没有引起窗体重绘。
- **解决**:在 `reFresh()` 末尾调用 `repaint()` 主动触发重绘。`update()` 只是把重绘事件丢进事件队列等会儿再处理,`repaint()` 会立刻执行 `paintEvent`。
- **话术**:"`update()` 是异步的、`repaint()` 是同步的,要立刻看到效果就得用后者。"

### 4. 歌曲在列表里重复显示

- **现象**:界面数据更新之后,列表里的歌会重复出现,越刷新越多。
- **原因**:存歌曲 ID 的 `musicOfPage` 和界面上的 `QListWidget` 里都已经有旧数据了,再往里加就变成两份。
- **解决**:每次刷新前先清空——`addMusicToMusicPage()` 里 `musicOfPage.clear()`,`reFresh()` 里 `ui->pageMusicList->clear()`。
- **话术**:"全量刷新的写法必须成对出现:先清空,再重建。"

## 三、播放控制阶段

### 5. 播放一首歌,该去哪个页面里找它的 ID?

- **现象**:`onCurrentIndexChanged(index)` 只给了播放队列里的下标,但要标记"已播放"就得知道这首歌的 ID,而歌曲 ID 存在各个 `CommonPage` 的 `musicOfPage` 里。三个页面都有这个列表,到底用哪个?
- **原因**:播放队列和页面列表是两套数据,下标只有在"用哪个页面的列表装进队列"这件事确定之后才有意义。
- **解决**:主窗口里维护一个 `CommonPage* currentPage`,初始指向 `localPage`;点"播放全部"和双击列表行的时候都会把 `currentPage` 改成当前播放的页面,之后就用 `currentPage->getMusicIdByIndex(index)` 反查歌曲 ID。
- **话术**:"索引本身没有意义,得先知道它是相对哪个列表的索引。"

### 6. 导航按钮上跳动的音符停在了错误的按钮上

- **现象**:播放另一个页面的歌曲时,跳动的音符动画还留在原来那个导航按钮上。
- **原因**:动画只在点击按钮时切换过,播放来源变了却没有同步。
- **解决**:写一个 `updateBtformAnimation()`:先用 `ui->stackedWidget->indexOf(currentPage)` 拿到当前页在堆叠窗口里的索引,再 `findChildren<BtForm*>()` 遍历所有导航按钮,`pageId` 等于该索引的显示动画、其余隐藏。**所有修改 `currentPage` 的地方都要调用它。**
- **话术**:"同一个状态被多处修改时,一定要有唯一的同步入口。"

### 7. 点击导航按钮时,窗口偶尔会自己移动

- **现象**:明明只是点了一下左侧导航按钮,窗口却跟着位移了。
- **原因**:点击时手抖或者鼠标轻微移动,Qt 可能把这次操作识别成鼠标移动事件,于是走进了拖拽窗口的逻辑。
- **解决**:加一个 `isDrag` 标志位。鼠标按下时默认置为 true;如果这次点击落在 `BtForm` 上,在 `onBtClicked()` 里把它设回 false。拖动时只有 `isDrag` 为 true 才移动窗口。
- **话术**:"两个功能抢同一个鼠标事件时,加一个状态位来区分意图。"

## 四、音乐加载阶段

### 8. 同一批歌曲被反复加载、数据库里出现重复记录

- **现象**:重复点"添加本地音乐",同一个目录下的歌会被反复加载进程序并写进数据库。
- **原因**:加载时没有对"已经加载过的文件"做过滤。直接遍历 `musicList` 去找时间复杂度是 O(n),数据一多就慢。
- **解决**:用 `QSet<QString>` 保存已经加载过的文件路径(查找接近 O(1)),加载前先 `contains()` 判断,不存在才解析和添加。
- **话术**:"去重别用线性查找,用哈希集合,顺手把复杂度从 O(n) 降到 O(1)。"

### 9. 重启程序后,去重又失效了(第 8 条的衍生问题)

- **现象**:加了去重之后,当时有效;但重启程序后再点加载,相同目录的歌还是能加进来一次,之后就进不来了。
- **原因**:程序启动时从数据库恢复歌曲只填了 `musicList`,没有把路径存进 `musicPaths`,所以启动后 `musicPaths` 是空的;等这次加载把路径写进去,之后才正常。
- **解决**:在 `readFromDB()` 里恢复每首歌时,同步把它的路径插入 `musicPaths`。
- **话术**:"只修了一半的 bug 更危险——内存里的两份索引必须一起维护。"

## 五、运行与发布

### 10. 程序被重复启动

- **现象**:每点一次 exe 就多一个实例,同一台机器上可以同时跑好几份。
- **原因**:程序默认不限制多开。
- **解决**:用 `QSharedMemory` 做单实例检测——启动时 `attach()` 成功说明已经有一份在跑,直接弹提示并退出;失败才 `create()`。多开的坏处也很明确:浪费内存和 CPU、多份实例同时改共享数据会导致数据不一致、同时访问数据库或文件会冲突、用户也容易混淆。
- **话术**:"先想清楚多开到底会坏什么事,再决定用什么机制拦住它。"

### 11. exe 拷给别人跑不起来

- **现象**:编译出来的 exe 拷到没装 Qt 的电脑上,双击提示缺少一堆 dll。
- **原因**:Qt 程序运行时依赖框架的库文件和平台插件,目标机器上没有。
- **解决**:用 release 版本编译(体积更小、效率更高),再用 `windeployqt` 自动收集依赖,把整个目录打包发出去。环境变量没配好时还会报 `Cannot find GCC installation directory`,需要把 Qt 的 bin 和 MinGW 的 bin 都加进 PATH。
- **话术**:"debug 是调试用的,发给别人一定要用 release 加部署工具。"

### 12. 调试输出太多,一个个删太麻烦

- **解决**:在 `.pro` 里加 `DEFINES += QT_NO_DEBUG_OUTPUT`,一句配置关掉所有 `qDebug`。

## 六、可以再补两条(来自你自己的代码)

这两条不在课件里,是你加子线程解析之后自己踩出来的,讲出来更能体现是"我做的"而不是"照着敲的"。

### 13. 加了子线程解析,第二次点"添加本地音乐"没反应

- **现象**:第一次添加本地音乐正常,第二次点就再也没反应了。
- **原因**:解析完把 `workFinished` 连到了 `QThread::quit`,线程的事件循环在第一批任务结束后就退出了,之后再发信号只是往一个已经停下来的循环里投事件。
- **解决**:让工作线程常驻(不再连 `quit`,只在析构时退出),或者每批任务用 `QThreadPool` / `QtConcurrent` 派发、用完自动回收。
- **话术**:"把耗时操作挪到子线程之后,线程的生命周期也要一起设计。"

### 14. 取消收藏后,"最近播放"标记到了别的歌上

- **现象**:播放列表里换歌时,偶尔会把另一首歌标记成已播放。
- **原因**:反查歌曲 ID 靠的是"播放队列里的第 n 首 = 页面列表里的第 n 行"这个假设。取消收藏会让页面少一行、播放新歌会让"最近播放"多一行,队列是播放那一刻定下来的,两边一旦顺序不一致,下标就指到了别的歌。
- **解决**:让播放队列自己存歌曲 ID(比如 `QVector<QString> playQueue`),按当前下标直接从队列里取 ID,界面列表只是它的一个视图。
- **话术**:"靠两个列表'顺序刚好一样'来关联,是最脆的耦合。"
