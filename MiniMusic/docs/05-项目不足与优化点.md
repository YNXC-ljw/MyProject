# 项目不足与优化点

> 用法:面试或答辩被问到"你这个项目有什么不足/还有哪些可以优化/如果重做会怎么做"时,照着这张表答。
> 每一条都按"现状 → 问题 → 怎么改 → 收益"组织。先说清楚不足在哪,再给出能落地的改法,比只说"功能还不够多"有说服力。

## 一、功能层面的不足(缺什么)

| 模块 | 现状 | 不足 / 影响 | 优化方向 |
| --- | --- | --- | --- |
| 在线音乐(推荐、电台、音乐馆) | 推荐页只是 39 张本地图片轮播,电台、音乐馆是空页面 | 没有数据来源,推荐位点了没反应,和"音乐馆"的定位不符 | 接入网络 API 拉歌单/榜单,封面和文字异步加载,点击进入歌单详情 |
| 搜索 | head 区搜索框只有控件,没有逻辑 | 歌曲一多就找不到 | 用 `QSortFilterProxyModel` 或直接对 `musicList` 过滤,按歌名/歌手/专辑匹配,可再加拼音首字母 |
| 换肤 | 点皮肤按钮只弹一个"暂未支持"的提示框 | 有入口没功能,面试官最容易点到的就是它 | 把散落在代码里的 `setStyleSheet` 抽成一个 `.qss` 文件,换肤 = 换 qss + 换主题色 |
| 本地歌曲管理 | 只能添加,不能删除、重命名、改标签、清空列表 | 加错歌只能去删数据库文件 | 列表右键菜单:从列表移除 / 从磁盘删除 / 打开所在文件夹;再加"清理失效歌曲" |
| 最近播放 | `isHistory` 只是一个 bool,顺序就是入库顺序 | 不是真正的"最近",反复听同一首也不会提前,也没有播放次数 | 表里加 `playCount`、`lastPlayTime`,按时间倒序取前 N 首 |
| 播放列表与续播 | 队列只在内存里,退出就没了,也不记"上次播放到哪" | 每次启动都要重新双击 | 用 `QSettings` 存上次歌曲、播放进度、音量、播放模式,启动时恢复 |
| 交互便捷性 | 不支持拖文件进窗口,没有快捷键,不响应键盘多媒体键 | 用起来不像一个桌面播放器 | `dragEnterEvent`/`dropEvent` 接收文件;`QShortcut`(空格播放暂停、左右切歌);原生事件过滤接多媒体键 |
| 桌面歌词 / 迷你模式 | 歌词只能从主窗口下拉显示 | 最小化后看不到歌词 | 单独做一个透明无边框歌词窗,或最小化时把迷你窗贴到桌面 |
| 音效 | 只有音量和静音 | 没有均衡器、倍速、淡入淡出 | 倍速可直接用 `setPlaybackRate`,均衡器可接 `QAudioProbe` 一类的处理链 |
| 歌词来源 | 只按同名 `.lrc` 文件找 | 没有 lrc 的歌永远没有歌词 | 加"歌词管理":手工指定 lrc、在线下载、读取音频内嵌歌词 |

## 二、代码与设计层面的不足(最值得讲的部分)

### 2.1 播放队列和界面列表靠"顺序一致"维系

现状:双击播放时先把播放队列清空,再按页面类型重新装歌;之后在 `onCurrentIndexChanged()` 里,用"队列里的第 n 首 = 页面列表里的第 n 行"这个假设,通过 `getMusicIdByIndex(index)` 反查歌曲 ID,用来标记"最近播放"。

问题:

- 任何一个页面 `reFrush()` 之后,列表的行数和顺序都可能变(取消收藏让"我喜欢"少一行,播放新歌让"最近播放"多一行),而队列是播放那一刻定下来的,两边就对不上了,**会把 A 歌标记成 B 歌播放过,甚至把收藏状态写到别的歌上**。
- `currentCommonPage` 记录的是"上一次点过的页面",点推荐/电台/音乐馆时不会更新,同样会错位。

改法:把播放队列提升成一个独立的数据结构(例如 `QVector<QString> playQueue` 存歌曲 ID),界面列表只是它的一个视图。当前播放到哪首,直接问队列要 ID,不再依赖界面行号。

### 2.2 容器与迭代器的用法

| 问题 | 位置 | 后果 | 改法 |
| --- | --- | --- | --- |
| 把迭代器捕获进 lambda | `commonpage.cpp` 的 `reFrush()`:`connect(listItem, ..., [=]{ it->setIsLike(...); })` | 这个 `it` 指向 `QVector<Music>` 的内部空间。只要之后 `musicList.push_back()` 触发了扩容(添加本地音乐就会),`it` 立刻变成悬垂迭代器,此时点"我喜欢"页的红心就是在写已释放的内存 | lambda 里改捕获 `musicId` 字符串,用到时再查一次 |
| O(n) 查找被放大成 O(n²) | `musiclist.cpp` 的 `findMusicById()` | `reFrush()` 里每首歌都要查一次,几百首歌就是几万次遍历;切歌、点收藏都要重建页面 | 加一个 `QHash<QString,int>` 做 ID 到下标的索引,查询变成 O(1) |
| 范围 for 按值拷贝 | `writeToDB()`、`addMusicToMusicPage()`、`addMusicToPlayList()` 里的 `for(auto music : musicList)` | 每次遍历都把 `Music`(三个 QString 加一个 QUrl)整个复制一遍 | 改成 `for(const Music& music : musicList)` |
| 列表全量重建 | `commonpage.cpp` 的 `reFrush()` | 点一次红心要重建三个页面的全部 ListItem | 只更新/增删变化的那一行;再进一步可以换成 Model/View |

### 2.3 健壮性(演示时最容易翻车的几个点)

| 问题 | 位置 | 说明 | 改法 |
| --- | --- | --- | --- |
| 成员变量没有初始化 | `widget.h` 的 `qint64 totalTime;`;`Music::Music()` 没给 `duration` 初值 | 构造函数里没赋初值,第一次用到时可能是一个随机值 | 声明时就写 `= 0` |
| 除以 0 | `onPositionChanged()` 里的 `position / (float)totalTime` | `totalTime` 为 0 时算出无穷大,进度条会被设成巨大宽度 | 加 `if(totalTime <= 0) return;` |
| 负索引没有拦住 | `getMusicIdByIndex()`,只判断了 `index >= size` | 播放队列清空、`currentIndex` 还是 -1 时,`musicOfPage[-1]` 是越界访问(QVector 不做边界检查) | 同时挡 `index < 0`;更彻底的做法是返回 bool 加输出参数,不要用 `" "` 当空值 |
| 忙等等不到头 | `Music::parseMediaMetaMusic()` 里的 `while(!isMetaDataAvailable()) processEvents();` | 遇到损坏或不支持的音频,这个循环永远出不来,解析线程直接卡死 | 加超时(用 `QElapsedTimer` 计时,超过 2 秒按文件名兜底);用 `QEventLoop` + `QTimer` 代替忙等;一个 `QMediaPlayer` 复用,不要每首歌都 new 一个 |
| 解析线程只能用一次 | `startMusicThread()` 里 `connect(musicWorker, &MusicWorker::workFinished, workThread, &QThread::quit)` | 第一批解析完线程的事件循环就退出了,之后再发 `startParseMusics` 只是往一个已经停掉的循环里投事件,**第二次点"添加本地音乐"不会有任何反应** | 要么让线程常驻(不连 `workFinished → quit`,只在析构里退出),要么每批任务用 `QThreadPool`/`QtConcurrent` 派发,用完自动回收 |
| 支持的格式白名单写了三份 | `musicworker.cpp`、`musiclist.cpp`(被关掉的那份)、`music.cpp` 的 `getLrcFilePath()` | 新增一种格式要改三处,容易漏 | 抽成统一的常量表或工具类 |
| 死代码 | `musiclist.cpp` 里整个 `addMusicsByUrl()` 被 `#if 0` 包住,但头文件里还留着声明 | 谁调用谁链接失败,读代码的人也会被误导 | 声明和实现一起删掉,功能已经搬到工作线程 |
| 播放错误没处理 | 没有接 `QMediaPlayer::error` / `mediaStatusChanged` | 文件被删、改名或 U 盘拔了,播放器静默不动,用户不知道发生了什么 | 接错误信号弹提示,并把这歌标记为"文件失效" |
| 用文件名猜元数据的兜底逻辑太脆 | `music.cpp` 里用 `filename.indexOf("-")` 和 `indexOf(".")` 取子串 | `01.稻香-周杰伦.mp3` 这种点号在横杠前面的,算出负长度,`mid()` 会取到一截乱字符串;歌名里带横杠也会切错 | 用 `QFileInfo::completeBaseName()` 拿主文件名,再用正则拆;负长度这个坑一定要堵 |
| 文案错误 | `music.cpp` 里 `musicSinger = "位置歌手";` | 应该是"未知歌手",而且和 02 文档里写的不一致 | 顺手改掉 |

### 2.4 数据持久化

| 问题 | 说明 | 改法 |
| --- | --- | --- |
| 只在退出时写库 | `writeToDB()` 只在托盘菜单的"退出"里调用;窗口没有重写 `closeEvent()`,所以 Alt+F4、任务管理器结束进程、直接关机都不会保存,收藏和最近播放会丢 | ① 重写 `closeEvent()`,把保存逻辑统一收口(并询问用户是"最小化到托盘"还是"退出");② 收藏和播放状态一变就写,或者打脏标记 + 定时批量写 |
| 没有事务 | 退出时循环把每首歌写库,每首两条 SQL(先 `SELECT EXISTS` 再 `INSERT`/`UPDATE`),没有事务包裹 | 用 `transaction()`/`commit()` 包起来;SQL 本身也可以合并成 UPSERT(`INSERT ... ON CONFLICT(musicId) DO UPDATE`) |
| 表结构没有版本管理 | 只有 `CREATE TABLE IF NOT EXISTS`,以后加字段不会自动迁移 | 用 `PRAGMA user_version` 记版本号,配合迁移脚本 |
| 数据库文件跟着工作目录走 | `setDatabaseName("MiniMusic.db")` 是相对路径,取决于从哪里启动;打包到 Program Files 后因为没有写权限会直接失败,只弹一个"数据库打开失败" | 用 `QStandardPaths::AppDataLocation` 拼绝对路径,启动时确保目录存在 |
| 数据库连接没释放 | 退出时只调了 `sqlite.close()`,没有 `QSqlDatabase::removeDatabase()` | 关闭后调用 `removeDatabase()`,避免 Qt 提示连接仍在使用 |
| 歌曲路径写死 | 存的是绝对路径,歌曲一移动或改名,记录就失效了 | 启动时校验文件是否存在,失效的置灰并提示;或者存相对路径加根目录 |

### 2.5 界面与交互细节

| 问题 | 位置 | 说明 | 改法 |
| --- | --- | --- | --- |
| 左侧导航和右侧页面不同步 | `on_addLocal_clicked()` 里只调了 `setCurrentIndex(4)` | 右边切到本地音乐页了,左边按钮还停在原来的高亮上,音符动画和 `currentCommonPage` 也没更新 | 把"切页"统一封装成 `switchPage(pageId)`,所有入口都走它 |
| 页面配图被封面顶掉 | `onMetaDataAvailableChanged()` 里调 `currentCommonPage->setMusicImage(封面)` | 页面左侧那张固定的"我喜欢/本地音乐/最近播放"配图被当前歌曲封面覆盖,切页也回不来 | 封面和页面配图用两个不同的控件,不要共用一个 `musicImageLabel` |
| 拖动进度条会被播放进度抢 | `setStep()` 和 `mouseMoveEvent()` 同时在改 `currentPos` | 拖动过程中 `positionChanged` 一直把滑块拉回去,手感很差 | 加 `isDragging` 标志,拖动期间忽略 `setStep`,松手后再恢复 |
| 进度条宽度取值时机不对 | `MusicSlider` 构造函数里的 `maxWidth = this->width()` | 构造时布局还没跑完,拿到的可能不是最终宽度 | 在 `resizeEvent()` 里更新 `maxWidth` |
| 高频调用 `setStyleSheet` | `moveSlider()`、`ListItem` 的进入离开事件 | 每次拖动、每次鼠标划过都重新解析一遍样式表,是 Qt 里很有名的性能坑 | 样式写进 `.qss`,或者用 `setProperty` + `style()->polish()`,只在状态真正变化时刷新 |
| 弹出面板的坐标是硬算的 | `on_volume_clicked()` 里的 `+15/+30`,`volumetool.cpp` 里的 25/205/180/300 | 换个尺寸或位置就错位;窗口贴着屏幕边缘时面板会跑到屏幕外 | 音量面板内部用布局排;弹出位置用 `QScreen::availableGeometry()` 夹一下 |
| 固定坐标导致只能禁用最大化 | `initWindow()` 里的 `ui->max->setEnabled(false)` | 界面上大量控件按坐标排死,最大化后无法适配,只好把最大化按钮禁掉 | 全部改用布局管理器;控件能自动伸展后,这个限制自然就能去掉 |
| 空状态没有提示 | 三个列表页在歌曲为空时 | 点"全部播放"什么都不会发生,用户以为程序坏了 | 空列表显示"还没有歌曲,点右下角添加";"播放全部"在空列表时置灰 |
| 推荐页目前只是外壳 | `recbox.cpp`、`recboxitem.cpp` | 39 张图洗牌后展示,但文字还是按洗牌后的下标拼的(`推荐-001` 和实际图片已经对不上);而且 `eventFilter` 把所有鼠标事件都吞掉了,推荐位点不动 | 图文一起洗(用同一个结构存图 + 文);`eventFilter` 只处理 Enter/Leave,其余返回 false;再接上点击动作 |
| 推荐位翻页会丢图 | `count = imageList.size() / col` | 39 张图,`col=4` 时只能看到 36 张,`col=8` 时只能看到 32 张 | 用 `(size + col - 1) / col` 向上取整,最后一页不足时补空位 |
| 翻页动画对象反复新建 | `recboxitem.cpp` 的 `eventFilter` | 鼠标快速划过时会有多个动画抢同一个 geometry | 复用一个成员动画对象 |
| 首次关窗口没有提示 | `on_quit_clicked()` 直接 `hide()` | 用户以为程序退出了,其实还在托盘里 | 第一次隐藏时用托盘气泡提示"已最小化到托盘" |
| 托盘菜单没挂父对象 | `QMenu* trayMenu = new QMenu();` | 轻微内存泄漏(`setContextMenu` 不接管所有权) | 改成 `new QMenu(this)` |

### 2.6 歌词解析的边界情况(LrcPage)

| 问题 | 说明 | 改法 |
| --- | --- | --- |
| 一行有多个时间戳时只认第一个 | `[00:01.00][00:05.00]副歌` 会把 `[00:05.00]副歌` 整段当成歌词文本显示出来 | 循环吃掉行首所有 `[..]`,每段各生成一条歌词 |
| 标签行被当成歌词 | `[ti:]`、`[ar:]`、`[by:]` 会被解析成"时间为 0、文本是乱码"的一条歌词 | 只解析匹配 `^\[\d+:\d+(\.\d+)?\]` 的行,其它当元信息跳过 |
| 编码写死 | 按 UTF-8 读,国内大量 lrc 是 GBK,会显示成乱码 | 用 `QTextStream` 读并处理 BOM,或者按 UTF-8、GBK 依次尝试解码 |
| 单行读取限制了长度 | `file.readLine(1024)` | 超过 1024 字节的行会被截断 | 用不带长度的 `readLine()` 或 `QTextStream::readLine()` |
| 找当前歌词是线性扫描 | `getLrcWordLineIndex()` 从第一行顺序比较,而 `positionChanged` 每次都会调它 | 行数一多就是白白的开销 | 时间戳本身有序,直接改成二分查找 |
| 不支持时间偏移标签 | lrc 里的 `[offset:]` 没有处理 | 有些歌词会整体偏早或偏晚 | 解析 offset 后统一做时间补偿 |
| 解析时逐行打印调试信息 | `parseLrcFile()` 里的 `qDebug()` | 几百行歌词会刷满控制台,也拖慢解析 | 删掉,或改用分类日志 |

## 四、优化路线(按优先级)

### P0 必须先做(不做会出功能性问题和崩溃)

1. **修解析线程第二次失效** —— 去掉 `workFinished → QThread::quit`,或改用 `QThreadPool`。这是"添加本地音乐"这个核心功能真正的可用性问题。
2. **修悬垂迭代器** —— `reFrush()` 的 lambda 改成捕获 `musicId`。
3. **补三个一行的保护** —— 成员初始化、除零判断、负索引判断。
4. **给忙等加超时** —— `QElapsedTimer` + `QEventLoop`,坏文件不再卡死。
5. **把保存时机和退出路径收口** —— 重写 `closeEvent()`,收藏/播放状态变化就写库。

### P1 短期内值得做(体验和性能)

6. 播放队列独立出来存 ID,修掉索引错位(见 2.1)。
7. 加 ID 索引,`reFrush()` 改成增量刷新。
8. 拖动进度条时不被自动刷新抢。
9. 统一 `switchPage(pageId)`,导航和页面永远同步。
10. 空状态提示 + 播放失败提示。
11. 最近播放加播放次数和最后播放时间。
12. lrc 解析补上多时间戳、标签行、编码和二分查找。

### P2 加分项(能讲出彩)

13. 用 Model/View 重构列表页,顺手把搜索做出来。
14. 加网络模块,推荐页接真实数据。
15. 统一 qss 实现换肤。
16. `windeployqt` + 安装包,项目能直接发给别人跑。
17. 补 QTest 用例和 CI。

分三层说,每层都要能落到具体位置:

1. 功能上,在线推荐、搜索、换肤这几个入口我留了界面但没做真实逻辑;本地歌曲也只能添加不能管理。这部分是我当时把时间都花在界面和播放链路上,取舍上的不足。
2. 设计上,我犯过一个比较典型的错误:播放队列和界面列表是靠"顺序一致"关联的,播放时按页面重建队列,之后再靠行号反查歌曲 ID。一旦页面刷新导致顺序变化,索引就会错位。如果重做,我会把队列单独抽出来存歌曲 ID,界面只是它的视图。
3. 工程上,我的持久化只在退出时写一次库,没有事务,退出路径也没有统一收口(没有重写 `closeEvent()`),这是会丢数据的;另外我没写任何测试。

**问:再给你时间,最想改哪三件事?**

① 把播放队列和界面解耦,顺带修掉索引错位;② 把界面刷新从"整页重建"改成按需更新,再进一步换成 Model/View;③ 把数据保存的时机和事务补上,让收藏、最近播放这些"用户以为已经存下来"的东西真的存下来。

**问:项目里哪里用了多线程?为什么?**

添加本地音乐时解析元数据是耗时的 I/O 加解码操作,放在主线程会让界面卡住,所以我把它放到一个工作线程里的 `MusicWorker` 上做,解析完用信号把 `QList<Music>` 传回主线程再刷界面。这一块我留了一个 bug:我把 `workFinished` 连到了 `QThread::quit`,导致第一批解析完线程就退出了,第二次添加不生效,正确做法是让线程常驻,或者改用 `QThreadPool` 和 `QtConcurrent`。这个问题也让我注意到跨线程传对象的约束:`Music` 是在子线程里构造的,一旦它内部碰了数据库连接就会出问题,所以数据库操作我全部留在主线程。

这一类的回答——"我知道它有问题、我知道怎么改、我踩过之后理解了原理"——比回答"没什么不足"要好得多。
